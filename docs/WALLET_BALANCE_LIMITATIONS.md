# ウォレット残高表示の範囲

## このアプリが表示する残高

SBT-JPYC-Payの残高欄は、選択中のJPYCコントラクトへ標準ERC-20 `balanceOf(接続アドレス)` を問い合わせた結果だけを「オンチェーン残高」として表示します。

次の値は合算・推定しません。

- ウォレットサービスの預入プールに移された残高
- Interest Vaultなどの運用先に移された残高
- 別アドレスへ転送された残高
- 非公開または非公式APIから得た値

したがって、預入・運用型ウォレットでは、表示がゼロでもサービス内残高がゼロとは限りません。決済受領の成否は残高差分ではなく、検証済みのTransferイベントと決済履歴で確認してください。

## Unifiについて確認できたこと

2026年8月13日時点の[Unifi Migration Guide](https://docs.unifi.me/Unifi-and-Unifi-Apps/Unifi-Migration-Guide)では、少なくともUSDTについて、自動預入後にオンチェーン残高がゼロになる場合があること、Unifiのアカウントプール・Interest Vaultへ預けられること、オンチェーン残高と預入残高を合算するSDKメソッドが案内されています。

[JPYCキャンペーン](https://promotion.unifi.me/referral-campaign-JPYC)ではUnifi内のJPYC残高に応じたリワードが案内されていますが、公開された開発者資料からは、JPYCについてUSDTと同じ合算残高APIが正式提供されることを確認できませんでした。

## 今回の対応範囲

- USDT向けメソッドをJPYCへ流用しません。
- Unifiの転送先・運用先アドレスをハードコードまたは追跡しません。
- アドレスやUser-Agentからウォレット種別を推測しません。
- Unifi SDKや新しい認証方式を追加しません。
- Kaiaの残高欄では、Unifiのサービス内残高を含まないことと、Unifiの残高表示・決済動作が未検証で正式サポート対象外であることを明示します。
- MetaMaskなど通常のウォレットでは、従来どおり接続アドレスのオンチェーンJPYC残高を表示します。

JPYCの正式な合算残高API、必要な認証、対応ウォレット接続方式が公式に確認できた場合は、別タスクで残高取得実装を追加します。
