# SBT-JPYC-Pay はじめての運用ガイド
## 公開PWAの試用・参加店舗の登録・Pinataの安全な扱い

SBT-JPYC-Payは、店舗でのJPYC決済と、SBTを使ったスタンプカードを試すための店舗向けアプリです。**PWAのインストール、店舗の登録、SBTの発行は、それぞれ別の操作です。**

## 1. 公開デモをPCで試す

1. Microsoft Edgeなどの対応ブラウザーで [公開デモ](https://shop.jpyc-pay.app/) を開きます。
2. アドレスバーにアプリのインストールアイコンが表示されたら、そこからインストールできます。インストールせず、ブラウザーのタブのままでも画面を確認できます。
3. まず画面の導線を確認します。ウォレットやコントラクトの動作を検証する場合は、運営者が案内したテストネットとテスト用ウォレットを使用してください。

PWAとしてインストールしても、同じ公開サイトをアプリ風のウィンドウで開く仕組みです。自分専用のサーバーや店舗ID、発行権限が作られるわけではありません。公開デモに実運用の認証情報を入力したり、実資金で取引を試したりしないでください。SBTの発行やオンチェーンの取引確認にはネット接続が必要です。

## 2. 運営管理者と参加店舗の流れ

| 立場 | 担当すること |
| --- | --- |
| **運営管理者**（SBTコントラクトのオーナー） | 利用ネットワークを決め、店舗IDと店舗のウォレットアドレスをコントラクトに登録する |
| **参加店舗**（登録されたウォレットの管理者） | 登録済みのウォレットで接続し、自店の設定やSBTテンプレートを管理する |
| **来店客** | 対応する顧客側アプリで決済用QRを読み取り、条件を満たした場合にSBTを受け取る |

### 運営管理者：店舗を登録する

1. 参加店舗から**店舗名、店舗が管理するウォレットの公開アドレス、発行に使うテンプレートのショップID**を受け取ります。秘密鍵、シードフレーズ、Pinataキーは受け取りません。
2. 対象ネットワークでコントラクトオーナーのウォレットを接続し、「ショップ管理」→「新しいショップを登録」で、重複しない1以上のショップID、ショップ名、店舗の公開アドレスを指定します。登録するIDと対象テンプレートのショップIDを揃えてください。
3. 登録トランザクションを確認し、店舗へ**利用するアプリのURL、ネットワーク、コントラクトの公開アドレス、店舗ID、登録したウォレットの公開アドレス**を伝えます。

### 参加店舗：登録されたウォレットで利用する

1. 案内されたアプリを開き、登録されたウォレットで接続します。すでにPWAをインストールしている場合は、そのアプリを開きます。
2. ネットワークと店舗IDを確認し、「設定」で自店の表示情報を整えます。「SBT管理」で対象テンプレートを確認し、管理者と照合します。スタンプの名称・画像・発行条件はテンプレートで設定します。
3. 権限が確認できなければ、まずネットワーク・店舗ID・接続アドレスを管理者の案内と照合します。**Pinataキーを登録しても、店舗の発行権限は付きません。**

**IDの見分け方:** PWAに付く `shop-…` はブラウザー側のインストール識別子で、登録欄の店舗IDではありません。テンプレートの「ショップIDをコピー」で得られる `0x…` は16進表記です。管理者の登録欄には、同じ値を10進数に直して入力します。

> 店舗の表示情報を設定することと、コントラクトに店舗を登録することは別です。現行の権限表示には固定のショップIDを参照する箇所があり、表示された権限と発行時に使用するショップIDが一致するとは限りません。決済QR経由の発行も固定IDを使用するため、複数店舗でそのまま使えるとは限りません。各店舗のウォレットと対象IDの組み合わせは、本番で案内する前にテスト環境で確認してください。

## 3. Pinataは何に使うか

Pinataは、SBTの画像と、その名前・説明・画像の参照先などを記載したデータ（メタデータ）をIPFSに置くためのサービスです。**Pinataキーはファイルをアップロードするための認証情報です。店舗の発行権限や、決済・ウォレットの鍵とは別物です。**

| 場面 | キーの扱い |
| --- | --- |
| **公開デモ・そこからインストールしたPWA** | 「IPFS / Pinata設定」に実キーを入れない。画面や導線を試す用途として使う。 |
| **画像をIPFSに置くだけ** | Pinataの管理画面から手動でアップロードできます。画像URLやCIDはファイルの参照先で、アップロード用の認証情報とは別です。 |
| **GitHubから取得して自前で運用** | 自分のVercelなどに立てても、フロントエンドの作りが同じならキーの扱いは変わりません。本番でアップロードを提供する場合は、サーバー側でキーを管理する仕組みを実装してから使います。 |

**現行実装では、画像のURLがあっても、そのURLだけで正常にSBTを発行できるわけではありません。** 発行時に画像・メタデータのPinataへのアップロード処理があるためです。画像が手動で公開済みでも、アプリからの発行手順を代替できるとは限りません。アップロードに失敗したときは、ウォレットで発行を承認しないでください。

### 自前運用でアップロードを実装する場合

- 実キーやJWTは、Vercelなどの**サーバー側の環境変数またはシークレット管理**に置き、サーバーの処理だけで読みます。Viteがブラウザーに渡す `VITE_` 付き変数や、ブラウザーに保存される設定欄には入れません。
- サーバーで操作する店舗を認証し、対象店舗への権限を確認します。その上で、サーバーがアップロードを行うか、用途を限定した短時間だけ有効な署名付きURLを発行します。
- 1つの公開PWAで各店舗が自分のPinataアカウントを使う構成では、店舗別の認証情報管理が別途必要です。プロジェクト共通の環境変数だけでは分けられません。

これは**本番向けの設計方針**で、現在のアプリにこのサーバー機能が実装されているという意味ではありません。過去に実キーを配布用JavaScriptへ含めたことが分かった場合は、環境変数を消すだけで済ませず、Pinata側で該当キーを失効させてください。
